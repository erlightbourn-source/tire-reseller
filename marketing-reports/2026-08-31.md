## ONE NEW FINDING — prompted by this week's safety audit

### N1. The `/pro` upgrade page's "simulated" disclaimer is static text, not tied to real Stripe state — same blind spot as today's flagged checkout bug
**Stage:** Trust → Conversion
**What & why:** Today's safety audit flagged (BACKLOG #23, flag-only, needs Evan) that
`app/api/stripe/checkout/route.js`'s dev-simulation branch has no production guard — if Stripe env
vars are ever unset/placeholder in prod, a POST there silently grants a free "active" subscription.
The UX-facing sibling of that same gap sits on `app/pro/page.js:57`: `"⚙️ Demo: upgrade is
simulated. Real billing uses Stripe."` is unconditional static text — it never imports or checks
`stripeConfigured()`, unlike `app/subscribe/page.js:26` which correctly branches on it
(`const live = stripeConfigured();`). Two ways this bites: (1) if Stripe *is* live in prod, this
page still tells a paying customer their $25/mo charge is fake, which reads as broken/untrustworthy
on the product's highest-priced tier; (2) it's the copy-level evidence of the exact same
"is-Stripe-really-configured" question the security finding raises at the code level — fixing
`/pro` to mirror `/subscribe`'s `stripeConfigured()` check would be one consistent tell instead of
two independent gaps. Copy-only fix (import + branch the string), same low-risk shape as
`/subscribe`'s existing pattern.
**Where:** `app/pro/page.js:57` (compare `app/subscribe/page.js:26,92`); `lib/stripe.js`
`stripeConfigured()`.
**Effort:** S · **Confidence:** High. Data-engineer-safe (mirrors an existing pattern, no new logic).
