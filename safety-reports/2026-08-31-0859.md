## (c) Proposed for review (all on `de/safety-20260831`, each build+test verified —
`npm test` and `APP_SECRET=… npm run build` green after every commit; schema
provider restored to `postgresql` before each commit)

1. **`2cb7326`** — SECURITY (high) — password-reset host-header poisoning →
   account takeover. `app/api/auth/forgot/route.js` built the emailed reset link
   from client-controlled `X-Forwarded-Host`/`Host`; middleware CSRF doesn't catch
   it because no-Origin requests pass through by design. Verified live with curl:
   pre-fix `X-Forwarded-Host: evil.example` → reset link points at
   `evil.example` with a valid 1-hour token; post-fix → always
   `shoptiretrader.com`. Fix: use the existing `SITE_URL` constant, matching every
   other email link in the app. BACKLOG #18.
2. **`aa5881e`** — SECURITY / data-integrity (high) — `prisma/seed.js`'s
   delete-everything-then-reseed had no production guard, and `DEPLOY.md:53` /
   `GO-LIVE.md:65` both list it as an optional prod step. Added
   `assertLocalDatabase()` (file:/localhost only, `ALLOW_REMOTE_SEED=1` escape
   hatch, credentials redacted in refusal output). Verified against 4 scenarios
   incl. the escape hatch. BACKLOG #19.
3. **`c460810`** — SECURITY (high) — the 2026-08-27 demo-admin remediation
   (`9b4b8c4`/`4272ed8`) covered only `demo@tiretrader.test`; the same seed
   creates 4 more publicly-credentialed accounts (`buyer@`, `mike@`, `rosa@`,
   `ken@`) — one Pro, one founding seller, all with seeded reviews.
   `scripts/neutralize-demo-admin.cjs` generalized to all 5 seeded accounts,
   idempotent, dry-run measured the exact gap (`already=1 would-fix=4`).
   **DECISION POINT / ACTION FOR EVAN: this ships the tool only — the 4 accounts
   are still live on prod until it's run there:**
   ```
   DATABASE_URL="<prod neon url>" node scripts/neutralize-demo-admin.cjs --dry
   DATABASE_URL="<prod neon url>" node scripts/neutralize-demo-admin.cjs
   ```
   Not run against prod by this routine (outward-facing action, out of scope).
   BACKLOG #20.
4. **`af511a3`** — SECURITY (medium) — per-account rate limits bypassable by IP
   rotation: 11 call sites passed the user id via `action` instead of `opts.key`,
   so the bucket key kept appending the IP rather than replacing it
   (`upload:<uid>:<ip>`), handing a full fresh quota per source address. A/B
   proven on real builds (pre-fix: 8 requests / 8 IPs → all 200; post-fix: 429 on
   the 6th). Touches 9 files but is a mechanical key-argument fix, not a
   refactor. BACKLOG #21.
5. **`cfc7002`** — SECURITY / privacy (medium) — EXIF/GPS stripping only covered
   JPEG uploads; PNG/WebP kept embedded GPS. `lib/image.js` now strips all three.
   Round-tripped real GPS-tagged test images to confirm removal without breaking
   decode. Suite 66→74. BACKLOG #22.

## (d) Flagged (needs a human — not fixed, not proposed)

- **HIGH — `app/api/stripe/checkout/route.js:19-29`** (BACKLOG #23): the
  dev-simulation branch is gated only on `stripeConfigured()`, with no
  `NODE_ENV`/deployment guard (unlike the sibling `/api/pro` route). If Stripe env
  vars are unset or still `REPLACE_ME` in production, any logged-in user gets a
  free 30-day "active" subscription on one POST — which also unlocks free Pro via
  `/api/pro`. Recommended fix mirrors `lib/auth.js:14-20`'s `IS_DEPLOYED`
  fail-closed pattern, but it's monetization/billing control flow — flag-only per

  values today** — local `.env` still shows `price_REPLACE_ME`.

  without `select` pulls another user's `passwordHash`/`email`/`resetTokenHash`/

  away from shipping password hashes.
- **LOW — `app/api/listings/route.js:66`, `[id]/route.js:80`** (BACKLOG #25):
